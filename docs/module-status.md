## Чем обоснованы неполные оценки

| Ячейка | Почему не ✅ |
|---|---|
| M-CORPUS · Вриф | Критерий §7 «правдоподобность» (слепая выборка: ревьюер не отличает копию от оригинала лучше случайного) требует живого человека — автоматизировать нечем |
| M-PROFILER · Unit | Юнитом покрыт только `addr_parse_ratio`; остальное проверяется интеграционно против живой БД — для интроспекции это осмысленнее, чем моки |
| M-PLAN-GRAPH · Unit | Юнит-теста нет: узлы графа — тонкие обёртки, вся логика в модулях под ними и покрыта их тестами; сам граф проверен интеграционно (гейт, resume, дифф) |
| M-POSTPROC · Вриф | Целевой recall NER ≥0.85 на целевом домене не измерен: в демо словарный NER, промышленный spaCy/Presidio подключается конфигом |
| M-REPORT · Unit/Интг/Сист | Тестов нет; страница проверена вручную в браузере на живом стенде + автопроверкой на отсутствие канареек в секции after |
| M-REPORT · Влд 🟡 | Единственное, что реально развёрнуто и доступно внешнему проверяющему (за basic-auth) |
| Влд (столбец) | Никто ещё не разрабатывал и не тестировал **на** санитизированной копии — главная ценность не подтверждена |

## Измеренные критерии приёмки §7

| Критерий | Порог | Факт |
|---|---|---|
| Полнота классификации | recall ≥0.98, precision ≥0.85 | **recall 1.000, precision 0.958** на 23 размеченных из 69 колонок |
| Канарейки | K/K в источнике, 0/K в копии | 10/10 и 0/10 на обоих входах |
| Отсутствие исходных значений | построчно `fake(x) ≠ x` | чисто по всем `direct`/`fake`/`generate` |
| Ссылочная целостность | все ограничения восстановлены | 30/30 |
| Объём | `count(*)` совпадает | 14 таблиц |
| Разнообразие | просадка энтропии ≤10% | в пределах порога |
| Сквозная консистентность | одна сущность → одна замена везде | таблица + склейка + свободный текст |
| Воспроизводимость | чек-суммы двух прогонов совпадают | подтверждено e2e |
| Несвязываемость копий | разные получатели → разные псевдонимы | подтверждено e2e |
| Вход «дамп» | тот же конвейер от файла | 8/8 критериев |
| **Верификатор умеет падать** | подсаженная утечка ловится | 3 негативных теста: канарейка, исходный ИНН, недостача строк |

**Не измерены:** производительность обоих проходов (демо-масштаб мал), доля ручного разбора ≤15%, recall NER, правдоподобность.

## Главный разрыв

**Левая ветвь закрыта полностью, правая — до «Вриф» включительно; провал на «Влд».** Все 14 модулей имеют код, контракты и место в графе `.grace`; 103 теста зелёные; сквозной прогон проходит на обоих входах ТЗ; ключевые критерии §7 теперь измерены, а не объявлены. Но валидация не начиналась: никто не разворачивал копию и не работал на ней.

Самый дешёвый шаг закрыть валидацию: **развернуть санитизированный дамп и прогнать на нём приложение, читающее эти таблицы.** Если ORM стартует, валидации ИНН/СНИЛС проходят и отчёты считаются — UC-2 и UC-3 закрываются за один прогон. Это и есть переход от «сделали по ТЗ» к «решили задачу»: платят за верификацию, ценность — в валидации.

## Что вскрыла сама эта ревизия

Составление отчёта оказалось диагностикой, а не бухгалтерией:

1. **Пять тестовых файлов, объявленных планом, не существовали** (`test_cli.py` и четыре интеграционных). Финальный гейт GRACE это пропустил: он прогоняет целевую команду `pytest tests/unit -q`, а не пофайловые команды задач. Дыра процесса, не только покрытия. Все пять дописаны.
2. **`os.environb` есть только на POSIX** — новый `test_cli.py` поймал это первым же запуском: на Windows CLI падал при старте. В контейнере не проявлялось.
3. **Одноимённые модули тестов в `unit/` и `integration/`** ломали совместный сбор pytest — раньше наборы никогда не запускались вместе. Добавлены `__init__.py`.
4. **Верификатор ни разу не проверялся на способность падать.** Три негативных теста закрыли этот вопрос — после истории с утечкой адресов, где он зеленел при частичном исправлении.
