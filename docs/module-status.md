## Чем обоснованы неполные оценки

| Ячейка | Почему не ✅ |

| M-CORPUS · Вриф | Критерий §7 «правдоподобность» (слепая выборка: ревьюер не отличает копию от оригинала лучше случайного) требует живого человека — автоматизировать нечем |
| M-PROFILER · Unit | Юнитом покрыт `addr_parse_ratio`; интроспекция каталога проверяется интеграционно против живой БД — для неё это осмысленнее моков |
| M-PLAN-GRAPH · Unit | Юнитом покрыт только `apply_overrides`; узлы графа — тонкие обёртки, вся логика в модулях под ними, сам граф проверен интеграционно (гейт, resume, подтверждение, дифф) |
| M-POSTPROC · Вриф | Целевой recall NER ≥0.85 на целевом домене не измерен: в демо словарный NER, третий эшелон (LLM) отсутствует физически — см. отклонение в §4.2 |
| M-REPORT · Unit/Интг/Сист | Тестов нет; страница проверена вручную в браузере на живом стенде + автопроверкой на отсутствие канареек в секции after. Демо-специфика оставлена сознательно (NonGoal изменения) |
| M-REPORT · Влд 🟡 | Единственное, что реально развёрнуто и доступно внешнему проверяющему (за basic-auth) |

## Измеренные критерии приёмки §7

| Критерий | Порог | Факт |
|---|---|---|
| Полнота классификации | recall ≥0.98, precision ≥0.85 | **recall 1.000, precision 0.958** на 23 размеченных из 69 колонок |
| Канарейки | K/K в источнике, 0/K в копии | **11/11** и 0/11 на обоих входах |
| Отсутствие исходных значений | построчно `fake(x) ≠ x` | чисто по всем `direct`/`fake`/`generate` |
| Ссылочная целостность | все ограничения восстановлены | 30/30 |
| Объём | `count(*)` совпадает | 14 таблиц |
| Разнообразие | просадка энтропии ≤10% | в пределах порога |
| Сквозная консистентность | одна сущность → одна замена везде | таблица + склейка + свободный текст |
| **Целостность не-ПДн** | текст, не являющийся ПДн, доезжает дословно | новая проверка; поймала бы порчу экранированием |
| **Сохранение связей** | связанные денежные колонки не расходятся | корреляция 1.000 → 0.9997 |
| **Валидность идентификаторов** | КС ИНН/СНИЛС/ОГРН верны в копии | 61/61 ИНН контрагентов валидны, включая 10-значные |
| **Уникальность под UNIQUE** | нет коллизий замен | 2001 табельный → 2001 уникальный |
| Воспроизводимость | чек-суммы двух прогонов совпадают | подтверждено e2e |
| Несвязываемость копий | разные получатели → разные псевдонимы | подтверждено e2e |
| Вход «дамп» | тот же конвейер от файла | 8/8 критериев |
| Верификатор умеет падать | подсаженная утечка ловится | 3 негативных теста |
| **Работа на чужой схеме** | конвейер собирается вне `hr` | план и артефакты на схеме `crm` |

**Не измерены:** производительность обоих проходов (демо-масштаб мал), доля ручного разбора ≤15%, recall NER, правдоподобность.

## Главный разрыв

**Левая ветвь закрыта полностью, правая — до «Вриф» включительно; провал на «Влд».** Все 14 модулей имеют код, контракты и место в графе `.grace`; 155 тестов зелёные; сквозной прогон проходит на обоих входах ТЗ и на посторонней схеме; критериев §7 измерено на пять больше. Но валидация не начиналась: никто не разворачивал копию и не работал на ней.

Самый дешёвый шаг закрыть валидацию: **развернуть санитизированный дамп и прогнать на нём приложение, читающее эти таблицы.** Если ORM стартует, валидации ИНН/СНИЛС проходят и отчёты считаются — UC-2 и UC-3 закрываются за один прогон. Это и есть переход от «сделали по ТЗ» к «решили задачу»: платят за верификацию, ценность — в валидации.

## Что вскрыли ревизии

**Разбор 4 (реализация), 2026-07-31.** Главный вывод был не про отдельные дефекты, а про сам тестовый набор: **103 зелёных теста проверяли код на данных, специально подобранных так, чтобы он работал.** В демо-базе не было ни одного 10-значного ИНН, ни одного табельного вне окна, ни одного обратного слэша, ни одной связи между зарплатой и начислениями. Ни одна из подтверждённых находок не была покрыта тестом. Отсюда порядок работы: сначала враждебные данные, потом правка, потом тест, который на старом коде красный.

Четыре пути утечки были невидимы для всех восьми проверок **одновременно** — по ним утечка и произошла бы на незнакомой базе.

**Предыдущая ревизия (V-модель), 2026-07-30.** Пять тестовых файлов, объявленных планом, не существовали; финальный гейт GRACE это пропустил, потому что прогоняет целевую команду, а не пофайловые команды задач. `os.environb` есть только на POSIX. Одноимённые модули тестов ломали совместный сбор pytest. Верификатор ни разу не проверялся на способность падать.
